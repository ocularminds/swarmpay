**Delivery phases and pull requests**

Each completed phase of the approved [architecture](architecture-and-delivery-plan.md) is reviewed as its own PR. The initial reviews were stacked as [foundation #1](https://github.com/ocularminds/swarmpay/pull/1) → [guarded payments #2](https://github.com/ocularminds/swarmpay/pull/2) → [Azure/product #3](https://github.com/ocularminds/swarmpay/pull/3) → [integration and verification #4](https://github.com/ocularminds/swarmpay/pull/4). These, [payment reliability/callback ingress #5](https://github.com/ocularminds/swarmpay/pull/5), [HTTPS/Azure handoff #6](https://github.com/ocularminds/swarmpay/pull/6), [evidence recovery/handoff #7](https://github.com/ocularminds/swarmpay/pull/7), [CI-bound image release #8](https://github.com/ocularminds/swarmpay/pull/8), [AKS deployment #9](https://github.com/ocularminds/swarmpay/pull/9), [agent egress/Decionis policy setup #10](https://github.com/ocularminds/swarmpay/pull/10), [sandbox under the local authority #13](https://github.com/ocularminds/swarmpay/pull/13), [judge-facing docs #14](https://github.com/ocularminds/swarmpay/pull/14), [venue, decline recovery and agent sourcing #15](https://github.com/ocularminds/swarmpay/pull/15), [landing #16](https://github.com/ocularminds/swarmpay/pull/16) and [dashboard #17](https://github.com/ocularminds/swarmpay/pull/17) (carried to `master` by #18) are merged. PR #4 integrated the intermediate phase merges into `master` after its full CI passed. Further phase reviews start from `master`. No automatic merges are configured. The repository remains private; public release is part of the submission phase.

A passing fixture test is recorded as local evidence; it does not close an external-account gate. Merging an implementation also does not verify those missing capabilities. Credentials stay in ignored local files. New external evidence should update the [capability matrix](implementation-status.md) before the account-backed demonstration is declared complete.

[PayPal provisioning and callback routing #12](https://github.com/ocularminds/swarmpay/pull/12) records the dedicated catering seller/app, both sandbox webhook registrations and the `/webhooks/paypal/{merchant}` public paths. Both seller OAuth checks and registration lookups pass against PayPal's API. Signature-verified delivery and the buyer/payment journey were verified in the October 28 live sandbox run.

The demo is hosted on `decionis-rg` / `decionis-aks` inside the existing `decionis` namespace, using deployment access from the refreshed Decionis Azure login. The [public demo](https://swarm.decionis.com) first ran five deployments using ACR run `cj3k`'s [verified image digests](../infra/azure/releases/d3ea860.images.json), where live network/database checks, trusted TLS, organizer access, both Azure assessments, the simulated payment/receipt journey and both evidence chains passed. Since October 28 it runs seven deployments with PayPal sandbox payments, recorded in the [sandbox release record](../infra/azure/releases/2026-10-28.sandbox.json). The new `swarm` DNS record was created only after TLS verification. No role assignments, namespace labels or existing Decionis deployments were changed. The [hosting runbook](azure-hosting.md) records the scope and operating limits.

The candidate hosted AgentSafe endpoints remain a separate capability gate: `swarm.decionisedge.com` is not serving a tenant, while `dci.decionisedge.com` requires its key. Current fleet configuration is inaccessible to this login, and the fleet runbook describes shadow mode. This phase keeps the visible local test authority; it does not claim hosted enforcement or change an existing tenant's upstream.
